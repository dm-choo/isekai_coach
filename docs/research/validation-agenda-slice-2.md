# Slice 2 validation agenda

## Validation target

이번 slice의 질문은 월드 타일 네 개가 존재하는가가 아니다. `중앙 방 확보 → 통로 정찰 → 경로 선택 → 누적 상태를 가진 전투 → 정책 수정 → 처음 보는 조합`이 하나의 원정 판단으로 이어지는지 검증한다.

## Gate order

```text
G0 상태와 재현성
→ G1 월드 타일 공간 판독
→ G2 중앙 방과 정찰 인과
→ G3 세 적의 전투 문법
→ G4 비용이 충돌하는 선택
→ G5 정책 수정 인과
→ G6 처음 보는 조합으로의 전이
→ G7 공개 build 완주
```

앞 gate가 실패하면 뒤에 콘텐츠를 추가하지 않고 원인 계약부터 수정한다.

## G0. State and reproducibility

자동 검증:

- 같은 world seed는 같은 최초 통로 인카운터를 생성한다.
- 저장·불러오기, 통로 왕복과 전투 재시도는 encounter generation을 바꾸지 않는다.
- `밝음 → 흐림` 재침식은 generation을 한 번 증가시키고 통로 구성을 다시 추첨한다.
- 다시 안정화한 뒤 또 재침식하면 새 generation을 다시 만든다.
- 재침식 뒤 시설·지형·소비한 일회성 보상은 복원되지 않는다.
- 동일한 encounter state와 입력은 동일한 combat event history를 생성한다.
- React와 Phaser는 월드·전투 authoritative state를 직접 변경하지 않는다.

## G1. World-tile spatial reading

관찰 과제:

1. 처음 진입한 참가자에게 현재 위치와 다음 타일 방향을 묻는다.
2. 중앙 방, 네 경계 방과 통로 구간의 관계를 자신의 말이나 손짓으로 설명하게 한다.
3. 봉쇄된 출구와 열린 출구를 구분하게 한다.

임시 통과 기준:

- 5명 중 4명이 중앙 방과 현재 경계 방향을 별도 설명 없이 맞힌다.
- 5명 중 4명이 동쪽 출구가 다음 월드 타일로 이어진다고 예측한다.
- 한 명이라도 전투 그리드 cell과 월드 타일을 같은 단위로 오해하면 용어와 축척 표현을 수정한다.

## G2. Scouting causality

검증할 인과:

```text
중앙 방 위협 해결
→ 네 통로가 동시에 정찰됨
→ 구간별 종류와 위치 공개
→ 정확한 적·사건 내용은 여전히 숨김
```

임시 통과 기준:

- 5명 중 4명이 통로가 공개된 이유를 중앙 방 클리어와 연결한다.
- 5명 중 4명이 `인카운터 위치·종류는 알지만 정확한 내용은 모른다`고 구분한다.
- 공개 효과를 놓치면 설명 문장을 늘리기 전에 중앙 방에서 네 방향으로 퍼지는 world-space 신호와 지도 상태 변화를 강화한다.

## G3. Enemy grammar

| 적 | 읽어야 하는 규칙 | 실패 신호 |
|---|---|---|
| 고블린 궁수 | 매우 긴 같은 행 사격, BODY 원점 | 단순 근접 공격으로 오해하거나 밀친 뒤 사격선 변화를 예측하지 못함 |
| 고블린 전사 | 여러 칸 접근 후 근접 공격 | 이동 경로를 피해 범위로 오해하거나 최종 도착점을 놓침 |
| 고블린 투척병 | 고정된 GROUND 착탄 지점 | 투척병을 밀면 착탄점도 움직인다고 예상함 |

각 적을 처음 본 직후 공격 대상, 이동 여부와 밀치기 뒤 변화를 질문한다. 5명 중 4명이 실제 해결 전에 세 항목 중 두 항목 이상을 맞히는 것을 임시 기준으로 삼는다.

## G4. Conflicting choices

고정된 핵심 상태에서 합법적인 행동 계획을 열거하고 결과를 다음 벡터로 비교한다.

```text
[클리어, 관리자 HP, 동료 HP, 소요 턴, 최종 위치]
```

- 타일 2와 4에는 각각 최소 두 개의 Pareto 비지배 계획이 있어야 한다.
- 한 행동이 모든 지표에서 다른 행동보다 좋으면 적을 추가하지 않고 시작 위치, AP, 목표 또는 피해를 조정한다.
- 하나의 policy 순서가 네 타일의 모든 고정 상태를 약한 우위로 해결하면 실패다.

플레이테스트 임시 기준:

- 5명 중 3명 이상이 자신이 포기한 것을 설명한다.
- 핵심 상태에서 최소 두 종류의 실제 선택이 나온다.
- 선택 이유가 체력, 시간, 사격선, 동료 보호 또는 이후 경로 중 하나와 연결된다.

## G5. Policy-edit causality

타일 2 뒤에는 다음만 보여준다.

- 동료가 실제로 실행한 policy 슬롯
- 그보다 위 슬롯이 실행되지 않은 첫 번째 이유
- 받은 피해와 소요 턴
- 기존 5-slot 목록의 순서 변경

임시 통과 기준:

- 5명 중 4명이 변경 뒤 타일 3의 첫 동료 행동을 예측한다.
- 5명 중 4명이 무엇이 바뀌었는지 이유를 설명한다.
- 타일 3에서 약속한 결과 지표 하나가 개선된다. 모든 지표가 동시에 개선될 필요는 없다.

## G6. Transfer

타일 4는 궁수·전사·투척병을 처음 보는 배치로 조합하고 추가 설명이나 두 번째 policy 수정을 제공하지 않는다.

- 5명 중 3명 이상이 새 tooltip 없이 대응한다.
- 참가자가 암기한 타일 번호가 아니라 사격선, 접근 경로, BODY/GROUND 같은 규칙을 판단 근거로 말한다.
- 실패가 나오더라도 원인을 적 규칙 또는 자신의 우선순위로 설명할 수 있으면 학습 신호로 기록한다.

## G7. Technical and public completion

- unit tests: 월드 생성, 재침식, 정찰, 타일 클리어, 지속 HP·시간, policy 순서와 세 적 Intent
- TypeScript `tsc --noEmit`
- production `/slice2/` base build
- 1280×720과 4:3 browser smoke
- 필수 흐름: 시작 → 타일 1 중앙 방 → 통로 정찰 → 타일 2 → policy 변경 → 타일 3 → 복합 타일 4 → 결과
- console, page와 failed request error 0건
- public root와 `/slice1/`이 기존 내용을 유지하고 `/slice2/`만 새 build를 제공

HTTP readiness, 테스트 통과 또는 네 타일 완주만으로 선택의 의미가 검증됐다고 주장하지 않는다.

## Stop rules

- G1이 실패하면 인카운터 종류를 늘리지 않는다.
- G2가 실패하면 정찰 설명 패널을 추가하기 전에 세계 공간의 원인·결과 연출을 수정한다.
- G3가 실패하면 피해 수치를 조정하기 전에 경로, 최종 위치와 anchor 표현을 수정한다.
- G4에 비용 없는 정답이 있으면 새 기술이나 하드 카운터 대신 위치, AP, 지속 HP와 목표를 조정한다.
- G5가 실패하면 policy 조건 문법을 확장하지 않고 기존 행동의 실행 가능 조건과 이유 표시를 수정한다.
- G6가 암기 문제가 되면 전투 RNG를 추가하지 않고 시작 배치와 적 조합을 바꾼다.
